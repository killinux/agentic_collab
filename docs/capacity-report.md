## 四、资源瓶颈分析

### 4.1 瓶颈排序

```
1. API 调用延迟 (占总时间 95%+)  ← 主要瓶颈
2. 串行执行 (agent 逐个处理)     ← 次要瓶颈
3. 硬件资源 (CPU/内存)           ← 不是瓶颈
```

### 4.2 详细分析

**API 延迟（主要瓶颈）**

模拟引擎是 IO 密集型：每步为每个 agent 调用多次 LLM API（感知、计划、行动、反思等），99% 的时间在等 API 返回。

- flash 平均 1.13 秒/次，plus 平均 0.88 秒/次
- 腾讯云到智谱的网络延迟很低（国内直连）
- 瓶颈在智谱服务端的推理耗时

**串行执行（次要瓶颈）**

当前代码对每个 agent 的认知循环（perceive → retrieve → plan → execute → reflect）是串行的。3 个 agent 串行处理完才进入下一步。

理论上同一步内的不同 agent 可以并行调用 API，但：
- 需要改动核心调度逻辑
- 受 GLM 并发限制（flash 5 并发，plus 2-5 并发）
- 25 agent 并行需要 25 并发，超出限制

**硬件资源（非瓶颈）**

| 资源 | 3 agent 占用 | 25 agent 预估 | 上限 | 余量 |
|------|-------------|--------------|------|------|
| CPU | <5% | <15% | 400% (4核) | 充足 |
| 内存 | ~300 MB | ~1.5 GB | 12 GB | 充足 |
| 磁盘 | ~50 MB/千步 | ~400 MB/千步 | 143 GB | 充足 |

**磁盘用量详估**（25 agent, 8640 步）：
- movement 文件: 8640 × ~5KB = ~43 MB
- environment 文件: 8640 × ~3KB = ~26 MB
- persona 记忆: 25 × ~10MB = ~250 MB
- 总计约 **320 MB**，磁盘完全不是问题

## 五、优化建议

### 5.1 推荐策略：混合模型

```
日常大规模模拟 → glm-4-flash（免费，速度快）
关键演示/对比 → glm-4-plus（质量好，短时间运行）
```

### 5.2 加速方案（如需实施）

| 方案 | 预期加速 | 改动量 | 风险 |
|------|---------|--------|------|
| 多 agent 并行 API 调用 | 3-5x | 中 | 触发并发限制 |
| 减少每步 API 调用（缓存重复 prompt） | 1.3-1.5x | 低 | 行为可能不够动态 |
| 降低认知频率（不是每步都反思） | 1.5-2x | 中 | 论文中有此设计 |
| 使用 Batch API（异步批处理） | 2-3x | 高 | 不适合实时模拟 |

### 5.3 推荐测试路径

```
第 1 步: 3 agent × 100 步 × flash       →  3 分钟   [已完成]
第 2 步: 3 agent × 100 步 × plus        →  5 分钟   [已完成]
第 3 步: 7 人选举 × 500 步 × flash       → ~40 分钟  [推荐下一步]
第 4 步: 25 人 × 100 步 × flash          → ~28 分钟
第 5 步: 25 人 × 1000 步 × flash         → ~4.7 小时
第 6 步: 25 人 × 8640 步 × flash         → ~41 小时（后台跑）
```

## 六、费用预估

### glm-4-flash

**完全免费**，无限量。所有场景均无费用风险。

### glm-4-plus

智谱定价（参考）: 输入 ~0.05 元/千 token，输出 ~0.05 元/千 token

| 场景 | API 调用 | 预估 token | 预估费用(RMB) |
|------|---------|-----------|--------------|
| 3 人, 100 步 | 317 | ~200K | ~20 元 |
| 3 人, 8640 步 | ~27K | ~17M | ~1,700 元 |
| 25 人, 100 步 | ~2,650 | ~1.7M | ~170 元 |
| 25 人, 8640 步 | ~229K | ~145M | ~14,500 元 |

> 注意：以上费用为粗略估算，实际费用取决于每次调用的 prompt 和 completion token 数量。建议在 `openai_config.json` 中设置 `cost-upperbound` 进行费用控制。

### 费用控制

`openai_config.json` 中的 `"cost-upperbound": 100.0` 字段会在累计费用超过阈值时停止模拟。但当前 GLM 的 cost 计算在代码中返回 0（因为 `model-costs` 设为 0），如需精确控制需填入真实单价。

## 七、结论

| 问题 | 结论 |
|------|------|
| 腾讯云硬件能跑多少 agent？ | **25 agent 完全没问题**，硬件有大量余量 |
| API 能支撑吗？ | **flash 完全支撑**（免费+无限量），plus 受费用和并发限制 |
| 25 人全天模拟可行吗？ | **可行**，flash 约 41 小时跑完，后台运行即可 |
| 主要瓶颈是什么？ | **API 调用延迟**，非硬件资源 |
| 推荐方案？ | 大规模用 flash，演示用 plus，混合使用 |
